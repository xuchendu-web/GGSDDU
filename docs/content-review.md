# 内容审核与下线机制

## 内容记录

每条内容必须包含：

- 唯一且永久不复用的 `id`
- `title`、`shortAnswer`、`reflectionQuestion`
- 对外展示的 `boundary`
- `category`、语义化 `version`
- `reviewStatus`: `draft`、`approved` 或 `offline`

首发库为 144 条结构化人工内容。运行时仅允许 `approved` 且未被远程下线的记录进入随机池。

## 编辑与合规双审

1. 编辑提交：检查表达清晰、卡片独立可读、反思问题可回答、无重复。
2. 编辑复核：核对事实中性、无暗示性行动建议、边界完整。
3. 合规复核：运行自动校验并人工检查禁用表达、个股/代码、产品名、目标价、收益承诺和确定性行情表述。
4. 发布批准：两名不同审核人分别记录编辑批准与合规批准，之后状态才可设为 `approved`。
5. 版本发布：内容变更必须提升版本；已产生的 `drawId` 永远保留原 `cardId` 映射，不得改写历史记录。

审核记录应保存在受控后台，至少包含内容 ID、版本、变更摘要、提交人、两名审核人、时间和决定。仓库中的首发数据只是发布产物，不能替代审核台账。

## 自动校验

`npm run validate:content` 检查：

- 总量在 120–200 条；
- ID、标题、短答、反思问题、边界、版本、状态和分类合法；
- ID 和正文组合无重复；
- 不出现高风险禁用词、证券代码、目标价、收益保证等模式；
- 所有首发记录均为 `approved`；
- 反思问题以问号结尾，边界明确教育用途。

自动校验只提供基础护栏，不能替代人工语境审核。

## 单条下线

1. 审核负责人把内容 ID 加入云数据库 `content_config/active.offlineCardIds`。
2. 云端新抽取立即排除该 ID。
3. 旧 `drawId` 还原时返回 `unavailable: true`，客户端不展示原文，也不替换成其他内容。
4. 记录原因、操作人、时间和受影响版本。
5. 修订内容用新版本重新走双审；确认后再从远程下线列表移除。

本地包仍含发布时白名单，常规下线应尽快提交小程序新版本移除对应内容。

## 紧急熔断

发现严重合规、版权或事实风险时：

1. 立即将受影响 ID 或全部 ID 加入远程下线列表；
2. 暂停分享入口或云函数抽取；
3. 在微信公众平台提交移除内容的紧急版本；
4. 对外说明采用“正视问题、已采取措施、机制升级”的口径，不淡化问题；
5. 完成根因复盘，更新禁用模式、审核清单和责任人后再恢复。

## 禁止留存

审核、日志与埋点均不得收集用户心中所想、自由文本问题、证券代码、持仓、通讯录或好友关系。任何新增字段必须先完成目的、最小必要性和保留期限评审。
