# 对话层资讯检索工具设计（借鉴 cn-web-search）

> 参考对象：[cn-web-search](https://github.com/joansongjr/cn-web-search)——一个聚合 17 个免费搜索引擎（百度/搜狗/360/必应/东方财富/财新/集思录/维基等）的 Agent Skill，纯网页抓取、零 API Key，以 SKILL.md 提示词形式指导 LLM 用 `web_fetch` 逐个抓搜索结果页并交叉验证。
>
> 结论先行：**借它的"多引擎聚合 + 财经源分类 + 多源交叉验证"思路，不借它的"提示词驱动"实现方式**。机构系统的检索必须是确定性工具，不能靠 LLM 现场读网页。已按此思路实现可运行原型：`prototype/news_search/search_provider.py`。

---

## 一、cn-web-search 评估：能借什么、不能照搬什么

| 维度 | cn-web-search 的做法 | 评估 | 我们的处理 |
|---|---|---|---|
| 多引擎聚合 | 17 个引擎按场景分类（公众号/中文/英文/财经/百科），给出选择建议表 | ✅ 核心价值：单引擎反爬或宕机时天然冗余；中文财经信息分散，聚合是刚需 | 借鉴，收敛为 5-6 个与投研相关的引擎，代码化为适配器 |
| 财经源意识 | 单列东方财富/集思录/财新等财经源 | ✅ 方向正确，但没有区分可信度 | 升级为**来源可信度分层 T1-T4**（官方公告>权威媒体>聚合搜索>社区） |
| 多源交叉验证 | 提示词建议"同一问题查 3 个引擎对照" | ✅ 思路对，但靠 LLM 自觉，无强制 | 工程化为 **corroboration 计数**：聚合器按标题相似度合并，自动统计跨引擎佐证数 |
| 零 API 依赖 | 纯网页抓取免费 | ⚠️ 适合个人 Agent；对机构系统，反爬风险与结果不稳定不可接受为唯一通道 | 作为兜底通道保留；客户环境优先接入其已采购的资讯 API（Wind 资讯/新闻库），网页抓取做降级冗余 |
| 提示词驱动 | 整个 Skill 就是一份 SKILL.md，LLM 现场决定抓哪个 URL、自己读 HTML | ❌ 不可审计、不可测试、结果结构不稳定、消耗大量上下文 | **改为确定性工具**：每个引擎一个解析器，输出统一 SearchResult 结构，LLM 只消费结构化结果 |
| 留痕 | 无 | ❌ 机构刚需缺失 | 每次检索生成快照 ID（查询、引擎轨迹、命中、时间），进证据包 |

## 二、在系统中的落位

```
对话层（F8）意图路由
   ├─ 数值/评分/组合类问题 → 信号引擎、评分引擎（确定性计算）
   ├─ 研究观点类问题     → 券商研报 RAG（通道2）
   └─ 时效资讯类问题     → news_search 工具（本设计）★
                             │
                             ├─ T1 官方通道：site:限定检索 中证指数/沪深交易所/证监会
                             ├─ T3 聚合通道：搜狗 / 360 / 必应中文（并行+去重+佐证计数）
                             ├─ T4 社区通道：集思录（仅线索，默认关闭）
                             └─ 快照留痕 → 证据包
```

触发 news_search 的典型对话意图（与标定清单联动）：

| 用户问题类型 | 标定清单关联项 | 检索策略 |
|---|---|---|
| "沪深300 最近有什么调样动态？" | D1.7 调样前瞻 | official 优先 + 聚合佐证 |
| "最近有什么政策对宽基有影响？" | D4.4 政策方向（事件清单+时效窗口） | 聚合通道，限时效 90 天 |
| "510300 最近有什么公告？" | D7.17 运作事件 | official（基金公司/交易所域名） |
| "市场对 A500 发行怎么看？" | D4.8 事件日历 | 聚合 + 社区线索（标注层级） |
| 报告生成中的"近期催化"小节 | 模板第 2.3 节 | 编排引擎自动调用，非对话触发 |

## 三、核心设计（对 cn-web-search 的四项工程化升级）

### 3.1 引擎适配器代码化

每个引擎一个解析函数（搜狗/360/必应/官方 site: 检索/集思录），输出统一结构：

```
SearchResult { title, url, snippet, engine, tier, fetched_at, corroboration, engines[] }
```

好处：可单测（解析器坏了立即报警而非静默给 LLM 垃圾）、可控成本（不再让 LLM 读 12000 字符的搜索页 HTML）、结果稳定。

### 3.2 来源可信度分层（T1-T4）与引用规则

| 层级 | 来源 | 报告/对话中的引用权限 |
|---|---|---|
| T1 官方 | 中证指数、沪深交易所、证监会、基金公司公告（site: 限定） | 可作事实与数字引用【来源：官方公告，日期】 |
| T2 权威财经媒体 | 白名单域名（财新、证券时报等，研究所定版） | 可作定性引用，标注媒体名 |
| T3 聚合搜索 | 搜狗/360/必应命中 | 仅作线索；佐证数 ≥2 可升级为"多源报道"级引用 |
| T4 社区 | 集思录等 | 仅作情绪线索，默认不进报告 |

**铁律**：news_search 结果不得产生任何数值结论——数字仍然只来自信号引擎（架构总原则"LLM 不算数"的延伸：**新闻也不算数**）。新闻中出现的数字（如"规模突破 2500 亿"）在报告中只能以"据报道"形式出现，且须与信号引擎数据比对，不一致时以信号引擎为准并标注差异。

### 3.3 交叉佐证（把"建议查 3 个引擎"变成机制）

聚合器按标题 bigram 相似度合并多引擎命中，自动输出 `corroboration` 计数与命中引擎列表；排序规则 = 先按可信层级、再按佐证数。对话回答中直接展示：「该消息获 2 个独立引擎佐证」。

### 3.4 留痕与降级

- 每次检索生成快照（NS-xxxx）：查询词、引擎轨迹（成功/失败/命中数）、全部命中、抓取时间——进证据包，客户可复核"当时搜到了什么"；
- 降级链：官方通道失败 → 聚合通道；单引擎失败自动跳过（engine_trace 记录）；全部失败返回明确的"检索不可用"，**禁止 LLM 凭记忆补答**；
- 部署要求：客户内网环境经统一出口代理访问外网，全部请求过审计日志（对应券商开发方案"联网搜索-内网代理-安全审计"的部署约定）；引擎清单与频控做成配置，反爬失效时热切换。

## 四、原型验证记录（2026-07-12）

代码：`prototype/news_search/search_provider.py`（requests + BeautifulSoup，约 250 行）

| 验证项 | 结果 |
|---|---|
| 多引擎并行 | 搜狗 9 条 + 360 9-10 条正常返回；必应中文/官方通道在本环境返回 0 条（重定向拦截），降级链正常跳过并在 engine_trace 中记录 |
| 交叉佐证 | 查询"沪深300ETF 华泰柏瑞 规模"：「规模突破 2500 亿元」同时被搜狗+360 命中，corroboration=2 正确合并 |
| 实效性 | 查询"沪深300 调样 2026"：命中中证指数公司 5 月 29 日调样公告转载（华工科技等调入、6 月 12 日生效）——正是 D1.7 调样前瞻需要的信息 |
| 快照留痕 | 每次返回 snapshot_id + engine_trace + usage_rule |

已知限制（生产化待办）：百度/东方财富/财新对数据中心 IP 返回 302 拦截，生产环境须走客户内网代理并补充这三个适配器；T2 权威媒体白名单待研究所定版；频控与缓存未实现。
